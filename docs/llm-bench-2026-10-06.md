# Banc LLM — incident FreeLLMAPI du 6 octobre 2026

## Résumé

- **Cause racine reproduite.** Avec `model: auto`, FreeLLMAPI a routé vers `dots3-note-preview` (OpenRouter). TanStack AI envoyait `tools` **et** `response_format: json_schema (strict)` dans la même requête (mode « combined »). Le modèle a répondu directement par un JSON conforme au schéma, sans appeler `getArticles`. Ce JSON contenait 5 UUID inventés, dont certains non hexadécimaux. `normalizeSelection` les a filtrés en silence, d'où `no_articles_selected`. Reproduction : 1 556 tokens d'entrée, contre 1 566 en prod, et aucun appel d'outil.
- **Le mode combined est un piège pour les modèles gratuits.** Il casse aussi nemotron-3.5-lightning (sélection vide sans appel), nemotron-3-super-120b (UUID inventé sans appel) et qwen3.8-27b (Groq refuse « json mode cannot be combined with tool calling »). En **deux temps** (boucle d'outils sans schéma, puis appel structuré sans outils), ces mêmes modèles appellent l'outil.
- **Les quotas gratuits sont le facteur limitant.** gemini-3.5-flash a atteint son quota journalier après environ 20 requêtes réussies. Cohere (command-a-*) et OpenRouter (nemotron) ont suivi dans l'heure. Brief consomme environ 20 requêtes par jour (3 catégories × ≈3 pour la sélection et ≈4 pour le résumé, retries non compris). Aucun modèle gratuit ne suffit seul.
- **Banc incomplet.** La sélection est mesurée (3 à 9 runs par finaliste). Le résumé ne l'est pas : 1 run exploitable sur un seul modèle. **La prod repasse sur OpenAI** en attendant.

## Liste blanche recommandée (provisoire)

À ne mettre en prod qu'après le banc résumé (5 runs × 3 catégories, `--judge`) :

1. **Principal :** `gemini-3.5-flash` (two-phase).
2. **Secours 1 :** `command-a-reasoning` (autre fournisseur, autre quota).
3. **Secours 2 :** `nemotron-3-super-120b`, seulement si la latence tient dans les délais (sélection 300 s, résumé 600 s).
4. **Repli final :** OpenAI `gpt-5.5`.

## Configuration FreeLLMAPI

- Ne plus utiliser `auto` pour Brief. Brief refuse désormais `FREE_LLM_MODEL=auto*`.
- Créer dans le dashboard une **Fallback Chain / un profil dédié à Brief** limité à la liste blanche, dans l'ordre ci-dessus. La failover in-group de FreeLLMAPI ne bascule alors qu'entre modèles validés.
- Retirer de la chaîne de Brief tout modèle signalé `lacks tool-calling` ou `format_ignored`, ainsi que les modèles OpenRouter `:free` non validés.
- Le succès HTTP de FreeLLMAPI ne vaut pas conformité : c'est Brief qui valide le protocole (voir plus bas).
- `/v1/models` liste des modèles absents du catalogue (claude-*) : il ne faut pas s'y fier pour construire la liste blanche.

## Protections ajoutées dans Brief (branche `fix/llm-tool-protocol-guards`)

- `FREE_LLM_MODEL` est obligatoire avec `LLM_PROVIDER=freellmapi`, et `auto*` est refusé au démarrage.
- L'adapter FreeLLMAPI envoie outils et schéma dans des **requêtes séparées** (two-phase) par défaut.
- `AI_PROTOCOL_VIOLATION`, avec retry, pour : une sélection rendue sans appel à `getArticles`, un id jamais servi par `getArticles`, un résumé écrit sans avoir lu chaque article sélectionné. Une sélection vide n'est acceptée que si `getArticles` a bien été appelé.
- Le message d'erreur réel du routeur (429, `empty_completion`…) est ajouté à l'erreur opaque de TanStack « structured output finalization produced no result ».
- `withDeadline` rejette même si `chat()` ne se termine pas après l'abort : deux runs du banc sont restés bloqués 16 min sans socket ouverte.

Reste à faire :
- un circuit breaker multi-modèles avec repli OpenAI dans Brief ;
- une confirmation explicite du modèle pour une sélection vide (champ dédié dans le schéma) ;
- les descriptions réelles des catégories dans le fixture, qui utilise aujourd'hui des placeholders.

## Reproduire

```sh
pnpm llm:fixture        # fige les flux du jour + pièges (bench/llm-fixture.json, hors git)
pnpm llm:reference      # sélection gpt-5.5 de référence + lot fixe du scénario résumé (OpenAI)
pnpm llm:test-tools     --models a,b --budget 60 --concurrency 2
pnpm llm:test-selection --models a,b --mode both --runs 1 --categories france
pnpm llm:benchmark      --models gemini-3.5-flash,command-a-reasoning --runs 5 --judge --budget 300
pnpm llm:benchmark      --models … --skip-from <dossier précédent>   # reprend sans refaire les runs acquis
pnpm llm:report         --from <dossier> --from <dossier>
```

Les résultats (`results.jsonl`, `exchanges.jsonl`, `live.jsonl`, `report.md`) vont dans `apps/category-worker/bench/results/`. Le banc consomme les mêmes quotas que le run de 7 h : il faut le lancer **après** le run du matin, avec une concurrence d'un modèle par fournisseur.
